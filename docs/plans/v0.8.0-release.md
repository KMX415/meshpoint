### Accepted release scope

Plugin manager, theme manager and Reticulum are desired v0.8.0 features.
ACARS, ADS-B, RTL433, DAB+, radio, pager protocols and DAPNET should be
available as selectable plugins. These integrations are not implemented yet.
Source baseline: javastraat `b18d6742de6c4cf7fb2e743c690400bea5790a9f`.

### Proposed packaging

- Keep existing Meshtastic and MeshCore capture, messaging, flashing and
  configuration available without installing or enabling any plugin.
- Include the managers and current default appearance in the base product.
- Offer optional apps and themes in a catalog. Download selected plugins;
  do not bundle every module or install SDR/RNS dependencies by default.
- Distinguish Available, Installed, Setup needed, Enabled and Failed states.
  Installing code must not start radios or silently join a TCP backbone.
- Resolve host dependencies before enablement, such as the RTL-SDR host.
  Preserve operator configuration on disable/update.
- Show hardware, download/system package and restart requirements up front.
  Use existing admin authorization and audit conventions.
- Pin reviewed catalog revisions and retain installed-source provenance.
  Catalog hosting and supported plugin revision policy still need selection.
- Optional dependencies must not silently upgrade packages used by core.
  Reject incompatible combinations until isolation is verified.

Einstein already provides source catalogs, selected-plugin downloads,
separate setup/enable steps, dependency probes and theme installation. His
fork also bundles disabled app plugins. Omitting those bundled payloads is
our packaging adaptation.

### Implementation order and regression gates

1. Hardware sign-off for the three reliability ports.
2. Manager foundations with no enabled plugins. Verify normal startup,
   existing routes and UI without optional dependencies installed.
3. Theme manager using our design tokens and existing dashboard shell.
4. One optional plugin end to end: catalog, download, setup, enable, restart,
   failure recovery, disable and uninstall. Do not copy wildcard root setup
   grants unchanged; review the privilege boundary first.
5. Reticulum via the plugin lifecycle: shared-instance rnsd ownership, LXMF,
   contacts, propagation, NomadNet browsing/hosting and telemetry.
6. Remaining optional radio modules with hardware-specific checks.

At each stage verify core capture, relay, USB reconnect/config/flash,
messages, authentication, preset filters, maps, backup and updates. Exercise
fresh installs and upgrades with no plugins, one plugin, a broken plugin,
missing dependencies and no network. Disabled modules must not open hardware
or start services. Preserve the cloud contract. No bulk merge of the fork.
Concentrator Reticulum remains out of scope.

## Architecture to port (his, confirmed working)

```
[RNode USB] ──serial──> rnsd (systemd, share_instance)
                              │
                              │ shared configdir RPC
                              ▼
                     meshpoint LxmfService (RNS client)
                              │
                              ├── messages table (protocol='reticulum')
                              ├── reticulum_peers table (announces)
                              └── REST + WS → Configuration + Reticulum UI
```

**Hard invariant:** `rnsd` must own the RNode / TCP interfaces. Meshpoint
attaches as a shared-instance client only. If meshpoint starts RNS first, it
brings up interfaces itself and RPC auth / digests break. Shared
`reticulum_config_dir` is mandatory (same path for both).

**Template for lifecycle:** MeshCore USB companion (opt-in, serial port
picker, release-before-flash, systemd-adjacent). Do not invent a third
companion pattern.

## Parked: SX1302 RNS (holy grail, not this sprint)

Concentrator RNS is attractive and still worth a later spike. Framing:

- MeshCore is **not** on the concentrator today, so `0x12` is free of
  MeshCore contention.
- Second sync domain on SX1302 is the **service** modem (multi-SF is one
  shared sync, already Meshtastic `0x2B`).
- Real tradeoff today is **LongFast (BW250) vs service for RNS**, not
  MeshCore.
- If MeshCore moves off 62.5 kHz (#945), concentrator MeshCore returns and
  then RNS vs MeshCore both want `0x12`.

Do not schedule Wave A until USB port has shipped or human explicitly
reopens.
