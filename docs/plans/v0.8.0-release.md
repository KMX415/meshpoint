## Architecture to port (his, confirmed working)

```
[RNode USB] ──serial──> rnsd (systemd, share_instance)
                              │
                              │ shared configdir RPC
                              ▼
                     meshpoint LxmfService (RNS client)
                              │
                              ├── messages table (protocol='reticulum')
                              ├── reticulum_peers table (announces)
                              └── REST + WS → Configuration + Reticulum UI
```

**Hard invariant:** `rnsd` must own the RNode / TCP interfaces. Meshpoint
attaches as a shared-instance client only. If meshpoint starts RNS first, it
brings up interfaces itself and RPC auth / digests break. Shared
`reticulum_config_dir` is mandatory (same path for both).

**Template for lifecycle:** MeshCore USB companion (opt-in, serial port
picker, release-before-flash, systemd-adjacent). Do not invent a third
companion pattern.

## Parked: SX1302 RNS (holy grail, not this sprint)

Concentrator RNS is attractive and still worth a later spike. Framing:

- MeshCore is **not** on the concentrator today, so `0x12` is free of
  MeshCore contention.
- Second sync domain on SX1302 is the **service** modem (multi-SF is one
  shared sync, already Meshtastic `0x2B`).
- Real tradeoff today is **LongFast (BW250) vs service for RNS**, not
  MeshCore.
- If MeshCore moves off 62.5 kHz (#945), concentrator MeshCore returns and
  then RNS vs MeshCore both want `0x12`.

Do not schedule Wave A until USB port has shipped or human explicitly
reopens.
